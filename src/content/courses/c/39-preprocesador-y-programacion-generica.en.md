> **Optional deepening path.** This lesson belongs to the advanced module *Modern C and C23*. It is not a requirement for the rest of the course; take it when you want to write code that is reusable across types or understand the macros you find in real libraries.

In `compilacion-y-enlazado` you saw that the **preprocessor** runs before the compiler: it copies `#include` files, replaces macros and chooses which parts of the code get compiled. So far you used it for constants and include guards. Here you learn to use it well, to recognize its traps and to combine it with other language tools to write **generic** code: code that works for several types without copying it by hand.

## Objectives

- Write macros with parameters without falling into the parentheses, double evaluation and multi-statement traps.
- Use the `#` (stringizing) and `##` (token pasting) operators.
- Write variadic macros with `__VA_ARGS__` and `__VA_OPT__`.
- Use conditional compilation to adapt code to the standard and the platform.
- Choose between an `inline` function and a macro.
- Write type-generic functions with `_Generic`.
- Compare two ways of building generic containers: `void *` with an element size and callbacks, or typed code generated by macros.

**Prerequisites:** `compilacion-y-enlazado`, `modularizacion-subprogramas-y-funciones`, `punteros-arreglos-y-estructuras` (function pointers and `qsort`), `memoria-dinamica` and `c23-moderno`.

## What a macro is

A **macro** is a name the preprocessor replaces with text before compiling. There are two kinds:

```c
#define CAPACITY 100            // object-like macro
#define SQUARE(x) ((x) * (x))   // function-like macro
```

The key to understanding them is this: **the preprocessor does not know C**. It knows nothing about types, precedence or how many times something is evaluated. It only replaces tokens. You can see the result with `gcc -E program.c` (or `cc -E`), as you did in `compilacion-y-enlazado`.

## The three macro traps

### Trap 1: parentheses

<!-- c-check: skip -->
```c
#include <stdio.h>

#define SQUARE_BAD(x) x * x
#define TWICE_BAD(x) (x) + (x)

int main(void) {
    printf("%d\n", SQUARE_BAD(2 + 1)); // expands to 2 + 1 * 2 + 1 = 5, not 9
    printf("%d\n", 10 * TWICE_BAD(3)); // expands to 10 * (3) + (3) = 33, not 60
    return 0;
}
```

The rule: **parenthesize every parameter and the whole expression**: `#define SQUARE(x) ((x) * (x))`.

### Trap 2: double evaluation

Even with all its parentheses, a macro copies the argument as many times as it appears. If the argument has a side effect, that effect happens several times:

```c
#include <stdio.h>

#define MAX(a, b) ((a) > (b) ? (a) : (b))

int main(void) {
    int i = 5;
    int j = 3;
    int m = MAX(i++, j); // ((i++) > (j) ? (i++) : (j))
    printf("m = %d, i = %d\n", m, i);
    return 0;
}
```

It prints `m = 6, i = 7`: `i` was incremented **twice**. With `SQUARE(i++)` it is worse: `((i++) * (i++))` modifies `i` twice with no sequence point between them, and that is **undefined behavior**. The rule: do not pass arguments with side effects (`++`, assignments, calls to functions that change something) to a macro. Better still: when you can, use a function.

### Trap 3: several statements

A macro that expands to several statements breaks inside an `if` without braces:

<!-- c-check: skip -->
```c
#define SWAP_BAD(a, b) int t = a; a = b; b = t;

if (x > y)
    SWAP_BAD(x, y)   // only "int t = x;" stays inside the if
```

The standard fix is to wrap the body in `do { ... } while (0)`: it is **a single statement**, runs exactly once, creates its own block for helper variables and requires the `;` when used, like a function call:

```c
#include <stdio.h>

#define SWAP_INT(a, b)   \
    do {                 \
        int tmp_ = (a);  \
        (a) = (b);       \
        (b) = tmp_;      \
    } while (0)

int main(void) {
    int x = 8;
    int y = 3;
    if (x > y)
        SWAP_INT(x, y);
    else
        puts("already in order");
    printf("%d %d\n", x, y);
    return 0;
}
```

The backslash `\` at the end of each line continues the macro on the next line.

## `#` and `##`: strings and token pasting

Inside a macro with parameters, `#parameter` turns the argument into a **string literal**, and `a ## b` **pastes** two tokens into one:

```c
#include <stdio.h>

#define SHOW_INT(expr) printf(#expr " = %d\n", (expr))
#define FIELD(n) field_ ## n

int main(void) {
    int width = 4;
    int height = 3;
    SHOW_INT(width * height); // prints: width * height = 12

    int FIELD(1) = 10; // declares field_1
    int FIELD(2) = 20; // declares field_2
    printf("%d\n", field_1 + field_2);
    return 0;
}
```

That is how `assert` works inside: it shows the text of the failed condition using `#`.

One detail: `#` stringizes the argument **without expanding it**. To stringize the **value** of another macro you need a second level:

```c
#include <stdio.h>

#define STRING(x) #x
#define EXPANDED_STRING(x) STRING(x)
#define VERSION 3

int main(void) {
    puts(STRING(VERSION));          // VERSION
    puts(EXPANDED_STRING(VERSION)); // 3
    return 0;
}
```

## Variadic macros: `__VA_ARGS__` and `__VA_OPT__`

A macro with `...` in its parameters accepts any number of arguments; inside it, `__VA_ARGS__` stands for those arguments (since C99). The classic use is a logging macro that adds information to every message:

<!-- c-check: skip -->
```c
#define LOG(fmt, ...) fprintf(stderr, "[%s:%d] " fmt "\n", __FILE__, __LINE__, __VA_ARGS__)

LOG("value = %d", x); // fine
LOG("start");         // error: a stray comma is left before the )
```

If you pass no variable arguments, the expansion ends in `..., __LINE__, )`, which does not compile. C23 solves this with **`__VA_OPT__(content)`**, which expands to `content` only if there are variable arguments:

```c
#include <stdio.h>

#define LOG(fmt, ...) \
    fprintf(stderr, "[%s:%d] " fmt "\n", __FILE__, __LINE__ __VA_OPT__(,) __VA_ARGS__)

int main(void) {
    int attempts = 3;
    LOG("start");
    LOG("attempts = %d", attempts);
    return 0;
}
```

> **Basic C:** from C99 to C17 the portable way was to require at least one argument after `fmt`, or to put the format inside `...`. GCC and Clang offered `, ## __VA_ARGS__` to delete the comma, but it is an **extension**.

> **Modern C (C23):** `__VA_OPT__` is standard in C23 (it already existed in C++20).

## Conditional compilation and feature checks

The `#if`, `#ifdef`, `#ifndef`, `#elif`, `#else` and `#endif` directives choose which code reaches the compiler. You already used them in include guards. They also adapt the program to the standard or the platform:

```c
#include <stdio.h>

#if __STDC_VERSION__ >= 202311L
    #define NULL_POINTER nullptr
#else
    #define NULL_POINTER NULL
#endif

#if defined(__has_include)
    #if __has_include(<threads.h>)
        #define HAS_THREADS_H 1
    #endif
#endif

int main(void) {
    int *p = NULL_POINTER;
    printf("p is null: %d\n", p == NULL_POINTER);
#ifdef HAS_THREADS_H
    puts("<threads.h> available");
#else
    puts("<threads.h> not available");
#endif
    return 0;
}
```

- `__has_include(<file>)` is 1 if the header exists. It is **standard** in C23; before, it was a GCC and Clang extension (that is why it is checked with `defined(__has_include)`).
- `__STDC_VERSION__` tells which standard is active (you saw it in `c23-moderno`).
- The macros `__STDC_NO_THREADS__`, `__STDC_NO_ATOMICS__` and `__STDC_NO_VLA__` announce missing optional parts.
- For a specific platform, compilers define macros such as `_WIN32`, `__linux__` or `__APPLE__` (they are not standard, but they are a very widespread convention).

> **Modern C (C23):** C23 adds `#elifdef` and `#elifndef` (shorthands for `#elif defined(...)`), and `#warning "message"`, which shows a warning without stopping compilation.

Use conditional compilation sparingly: every branch is code that only compiles on some machines, and a bug in it can go unnoticed. Keep platform differences in a single file.

## `inline` or macro

A function-like macro avoids the cost of a call, but it has all the traps you saw. Since C99, an **`inline`** function suggests that the compiler replace the call with the body, and it keeps everything good about a function: checked types, each argument evaluated once, and it can be debugged.

```c
#include <stdio.h>

static inline int max_int(int a, int b) {
    return a > b ? a : b;
}

int main(void) {
    int i = 5;
    int m = max_int(i++, 3); // i++ is evaluated only once
    printf("m = %d, i = %d\n", m, i);
    return 0;
}
```

It prints `m = 5, i = 6`, as expected. Two details:

- `inline` is a **hint**: with optimization (`-O2`), compilers decide on their own which functions to expand, with or without `inline`.
- In C, an `inline` function without `static` defined in a header has subtle linkage rules: if the compiler decides not to expand it, the linker looks for an external definition that does not exist and fails with *undefined symbol*. The simple, safe form is **`static inline`** in the header.

When do you still need a macro? When you need something a function cannot do: use `#` or `##`, know `__FILE__` and `__LINE__` of the call site, receive a **type** as an argument or work with any type. For everything else, prefer a function.

## `_Generic`: one function for several types

C has no function overloading: there cannot be two `absolute_value` functions, one for `int` and another for `double`. C11 added **`_Generic`**, a **compile-time** selection based on the type of an expression:

```c
_Generic(expression, type1: result1, type2: result2, default: default_result)
```

The compiler looks at the type of `expression` (without evaluating it) and keeps the result of the matching branch. Combined with a macro, it gives a **type-generic interface**:

```c
#include <stdio.h>
#include <stdlib.h>
#include <math.h>

#define ABSOLUTE(x) _Generic((x), \
    int: abs,                     \
    long: labs,                   \
    double: fabs                  \
)(x)

#define FORMAT(x) _Generic((x), \
    int: "%d",                  \
    long: "%ld",                \
    double: "%g",               \
    char *: "%s",               \
    const char *: "%s"          \
)

#define PRINT(x) (printf(FORMAT(x), (x)), putchar('\n'))

int main(void) {
    PRINT(ABSOLUTE(-4));
    PRINT(ABSOLUTE(-7L));
    PRINT(ABSOLUTE(-2.5));
    PRINT("hello");
    return 0;
}
```

It prints `4`, `7`, `2.5` and `hello`. `ABSOLUTE` chooses **the function** (`abs`, `labs` or `fabs`) and then calls it with `(x)`. That is how `<tgmath.h>`, the standard header of type-generic math, is built.

Rules worth knowing:

- The controlling expression is **not evaluated**; only its type matters. That is why in `ABSOLUTE`, although `x` appears twice, it is evaluated only once: in the call `(x)`.
- The type is taken after lvalue conversion: `const int` counts as `int`, and an array as a pointer (the string `"hello"` is `char *`).
- If no type matches and there is no `default`, it is a compile error: a good way to reject unexpected types.
- `char`, `signed char` and `unsigned char` are three different types, just like `int` and `long`.

## Generic containers: two strategies

Imagine a **dynamic vector** (an array that grows) that works for any type. C has two classic ways to write it.

### Strategy 1: `void *`, element size and callbacks

This is the strategy of `qsort`, which you saw in `punteros-arreglos-y-estructuras`: the container stores **bytes** without knowing what they are. For that it needs three things: a `void *` to the data, the **size of each element** and, for operations that depend on the type (compare, print), **callback functions** supplied by the user.

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

typedef struct {
    void *data;
    size_t element_size;
    size_t count;
    size_t capacity;
} Vector;

// Ownership: the caller owns the vector and releases it with vector_destroy.
bool vector_init(Vector *v, size_t element_size) {
    v->element_size = element_size;
    v->count = 0;
    v->capacity = 4;
    v->data = malloc(v->capacity * element_size);
    return v->data != NULL;
}

// Copies element_size bytes from element to the end of the vector.
bool vector_push(Vector *v, const void *element) {
    if (v->count == v->capacity) {
        size_t bigger = v->capacity * 2;
        void *other = realloc(v->data, bigger * v->element_size);
        if (other == NULL) {
            return false; // the original vector is untouched
        }
        v->data = other;
        v->capacity = bigger;
    }
    char *dest = (char *)v->data + v->count * v->element_size;
    memcpy(dest, element, v->element_size);
    v->count++;
    return true;
}

void *vector_at(const Vector *v, size_t i) {
    return (char *)v->data + i * v->element_size;
}

void vector_for_each(const Vector *v, void (*action)(const void *)) {
    for (size_t i = 0; i < v->count; i++) {
        action(vector_at(v, i));
    }
}

void vector_destroy(Vector *v) {
    free(v->data);
    v->data = NULL;
    v->count = 0;
    v->capacity = 0;
}

void print_double(const void *p) {
    printf("%.1f ", *(const double *)p);
}

int main(void) {
    Vector v;
    if (!vector_init(&v, sizeof(double))) {
        return 1;
    }
    for (int i = 1; i <= 6; i++) {
        double x = i * 1.5;
        if (!vector_push(&v, &x)) {
            vector_destroy(&v);
            return 1;
        }
    }
    vector_for_each(&v, print_double);
    putchar('\n');
    vector_destroy(&v);
    return 0;
}
```

The arithmetic uses `char *` because a `char` takes exactly one byte: `(char *)v->data + i * element_size` is the address of element `i`.

**Advantages:** a single compiled code for every type; works in any C version. **Disadvantages:** the compiler **does not check types** (if you push an `int` into a vector of `double`, nobody warns you), every access needs a cast, and calls through function pointers are harder to optimize.

### Strategy 2: typed code generated by macros

The other strategy uses the preprocessor as a **template**: a macro that, for each type, generates the structure and its functions with their own names thanks to `##`.

```c
#include <stdio.h>
#include <stdlib.h>

#define DEFINE_STACK(T, NAME)                                     \
    typedef struct {                                              \
        T *data;                                                  \
        size_t count;                                             \
        size_t capacity;                                          \
    } NAME;                                                       \
                                                                  \
    static inline bool NAME##_push(NAME *s, T value) {            \
        if (s->count == s->capacity) {                            \
            size_t bigger = s->capacity == 0 ? 4 : s->capacity * 2; \
            T *other = realloc(s->data, bigger * sizeof(T));      \
            if (other == NULL) {                                  \
                return false;                                     \
            }                                                     \
            s->data = other;                                      \
            s->capacity = bigger;                                 \
        }                                                         \
        s->data[s->count++] = value;                              \
        return true;                                              \
    }                                                             \
                                                                  \
    static inline T NAME##_pop(NAME *s) {                         \
        return s->data[--s->count];                               \
    }                                                             \
                                                                  \
    static inline void NAME##_free(NAME *s) {                     \
        free(s->data);                                            \
        s->data = NULL;                                           \
        s->count = 0;                                             \
        s->capacity = 0;                                          \
    }

DEFINE_STACK(int, IntStack)
DEFINE_STACK(double, DoubleStack)

int main(void) {
    IntStack ints = {};
    DoubleStack reals = {};
    for (int i = 1; i <= 5; i++) {
        if (!IntStack_push(&ints, i) || !DoubleStack_push(&reals, i / 2.0)) {
            IntStack_free(&ints);
            DoubleStack_free(&reals);
            return 1;
        }
    }
    while (ints.count > 0) {
        printf("%d ", IntStack_pop(&ints));
    }
    putchar('\n');
    printf("real top: %.1f\n", DoubleStack_pop(&reals));
    IntStack_free(&ints);
    DoubleStack_free(&reals);
    return 0;
}
```

`DEFINE_STACK(int, IntStack)` generates the `IntStack` type and the functions `IntStack_push`, `IntStack_pop` and `IntStack_free`, all with a real `int`.

**Advantages:** the compiler **checks types** (pushing a `char *` onto an `IntStack` is an error), there are no casts or callbacks, and the code is as fast as hand-written code. **Disadvantages:** one compiled copy per type, compile errors point at the macro line instead of the real problem, and the macro is hard to read and debug.

| | `void *` + size + callbacks | Macros that generate code |
| --- | --- | --- |
| Type checking | no | yes |
| Compiled code | one for every type | one per type |
| Ease of debugging | good | poor |
| Performance | indirect calls | same as hand-written code |
| Example in the library | `qsort`, `bsearch` | `<tgmath.h>` (with `_Generic`) |

Neither is always better. For a small, clear library `void *` is usually enough; when performance or type safety matter a lot, macro generation is preferred.

## `typeof` in macros

With `typeof` (standard in C23, you saw it in `c23-moderno`) a macro can declare variables **of the type of its argument**. That solves generic swapping:

```c
#include <stdio.h>

#define SWAP(a, b)              \
    do {                        \
        typeof(a) tmp_ = (a);   \
        (a) = (b);              \
        (b) = tmp_;             \
    } while (0)

int main(void) {
    int x = 1;
    int y = 2;
    double p = 1.5;
    double q = 2.5;
    SWAP(x, y);
    SWAP(p, q);
    printf("%d %d %.1f %.1f\n", x, y, p, q);
    return 0;
}
```

For a `MAX` that evaluates each argument only once, you would have to store each argument in a `typeof` variable and return a value from a block; that requires *statement expressions* `({ ... })`, which are a GCC and Clang **extension**, not standard C. In standard C, the answer is one `static inline` function per type, chosen with `_Generic`.

> **Portability:** before C23, `typeof` was an extension (`__typeof__` in GCC and Clang). If your code must compile as C17, use `__typeof__` knowing it is not standard, or avoid `typeof`.

## Common mistakes

- Forgetting parentheses around the parameters or the body of a macro.
- Passing `i++` or a call with side effects to a macro that repeats its argument.
- Writing multi-statement macros without `do { } while (0)`.
- Putting `;` at the end of a macro definition: the statement that uses it ends with `;;` or breaks an `if`/`else`.
- Using `inline` without `static` in a header and getting a linker error.
- Believing `_Generic` evaluates its controlling expression, or expecting it to distinguish `const int` from `int`.
- Using `({ ... })` or `, ## __VA_ARGS__` believing they are standard.

## Summary

- A macro replaces text: parentheses everywhere, beware of double evaluation, and `do { } while (0)` for several statements.
- `#` turns an argument into a string; `##` pastes tokens.
- `__VA_ARGS__` receives variable arguments; `__VA_OPT__` (C23) adds text only if there are any.
- `#if`, `__has_include` and `__STDC_VERSION__` adapt the code to the standard and the platform.
- Prefer `static inline` to a macro whenever a function is enough.
- `_Generic` picks an expression by type, at compile time.
- Generic containers: `void *` + size + callbacks (simple, no type checking) or code generated by macros (typed, harder to maintain).

### Exercise 2: a checking macro

Write a macro `CHECK(cond)` that, if `cond` is false, prints the text of the condition, the file and the line to `stderr`, and ends the program with `EXIT_FAILURE`. It must be usable in an `if` without braces.

<details><summary>Show solution</summary>

```c
#include <stdio.h>
#include <stdlib.h>

#define CHECK(cond)                                           \
    do {                                                      \
        if (!(cond)) {                                        \
            fprintf(stderr, "%s:%d: check failed: %s\n",      \
                    __FILE__, __LINE__, #cond);               \
            exit(EXIT_FAILURE);                               \
        }                                                     \
    } while (0)

int main(void) {
    int divisor = 4;
    if (divisor != 0)
        CHECK(divisor > 0);
    else
        puts("zero divisor");
    printf("%d\n", 100 / divisor);
    return 0;
}
```

`#cond` turns the condition into a string; `do { } while (0)` makes it safe inside the `if`.

### Exercise 3: `_Generic` for type names

Write a macro `TYPE_NAME(x)` that returns the string `"int"`, `"double"`, `"char *"` or `"other"` depending on the type of `x`. What does it return for `'a'`? And for `3.0f`?

<details><summary>Show solution</summary>

```c
#include <stdio.h>

#define TYPE_NAME(x) _Generic((x), \
    int: "int",                    \
    double: "double",              \
    char *: "char *",              \
    default: "other"               \
)

int main(void) {
    printf("%s\n", TYPE_NAME(42));
    printf("%s\n", TYPE_NAME(2.5));
    printf("%s\n", TYPE_NAME("hello"));
    printf("%s\n", TYPE_NAME('a'));
    printf("%s\n", TYPE_NAME(3.0f));
    return 0;
}
```

`'a'` returns `"int"`: in C, a character constant has type `int`. `3.0f` is a `float`, which has no branch, so it returns `"other"`.

### Exercise 4: search with callbacks

Add to the lesson's generic `Vector` a function `size_t vector_find(const Vector *v, const void *key, int (*compare)(const void *, const void *))` that returns the index of the first element equal to `key` (when `compare` returns 0), or `v->count` if it is not found. Write the comparator for `double`.

<details><summary>Show solution</summary>

```c
size_t vector_find(const Vector *v, const void *key,
                   int (*compare)(const void *, const void *)) {
    for (size_t i = 0; i < v->count; i++) {
        if (compare(vector_at(v, i), key) == 0) {
            return i;
        }
    }
    return v->count;
}

int compare_double(const void *a, const void *b) {
    double x = *(const double *)a;
    double y = *(const double *)b;
    return (x > y) - (x < y);
}
```

Usage: `double key = 4.5; size_t i = vector_find(&v, &key, compare_double);`. The comparator follows the same convention as `qsort`'s, so you can reuse it for sorting.

</details>
